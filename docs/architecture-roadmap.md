# 半拍技术架构演进计划

更新于 2026 年 11 月 10 日。

半拍继续采用 React、TypeScript、Tauri、Rust、OpenSheetMusicDisplay 和 Three.js，围绕渐进式钢琴课程、MIDI 实时练习、完整曲谱及手势示范演进。近期优先整理练习引擎和时间基准，随后完善乐谱模型与持久数据层。

实施顺序依据当前个人使用、Windows 桌面优先、后续扩展多平台的需求安排。已完成的子项在对应章节勾选。

## 技术选型与职责

| 技术 | 承担的职责 | 演进重点 |
| --- | --- | --- |
| React 与 TypeScript | 学习页面、练习控件、进度和反馈 | 将练习运行状态与组件生命周期解耦，控制高频界面更新 |
| Tauri 与 Rust | 桌面宿主、原生 MIDI、文件和数据库访问 | 完善设备生命周期与原生接口，按平台验证行为 |
| OpenSheetMusicDisplay | MusicXML 乐谱排版、谱面交互 | 长谱分段呈现、布局缓存、稳定的音符与光标映射 |
| Three.js 与现有 Ultraleap 手模 | 键盘、骨骼手模、镜头和教学动作 | 精细动作数据、动作过渡与教学可观察性 |
| Web Audio | 钢琴采样、示范、伴奏和节拍器 | 时钟对齐、延迟测量、音色质量及资源调度 |
| SQLite | 拟新增的桌面持久数据层 | 学习记录、曲谱元数据、版本迁移与恢复 |

Tauri 的原生核心与系统 WebView 可以分别承担设备能力和界面呈现。各系统使用不同 WebView，跨平台验证应覆盖音频、图形和设备行为。[Tauri 进程模型](https://v2.tauri.app/concept/process-model/)

## 提取练习引擎

### 当前实现

`src/practiceEngine.ts` 接收课程、选段、练习设置和带时间戳的按键事件，复用 `Judge` 判分。引擎从注入的播放接口读取音频时钟，安排预备拍、节拍器、示范和伴奏。暂停保留已命中的音及当前位置，续练重新安排预备拍和剩余伴奏。每轮从开始起持有唯一标识，结束时只产生一次结算。

`src/useStudio.ts` 通过 React 的 `useSyncExternalStore` 订阅引擎，负责设备连接、实时试听、循环重启和本地保存。成绩按轮次标识去重。播放位置仍由练习室顶层订阅，光标、琴键和 3D 视图的刷新开销仍需分开测量。

### 实施任务

- [x] 将开始、预备拍、练习、示范、暂停、恢复和结束整理为显式状态与事件，定义每个状态允许的操作。
- [x] 提取可独立运行的练习引擎，接收课程时间线、练习设置和输入事件，输出状态快照、反馈及成绩。
- [x] 将 MIDI、音频和存储通过小型接口接入，支持使用可控时钟和模拟输入验证练习行为。
- [ ] 让 React 订阅必要的状态变化。将光标、琴键和 3D 动画的刷新频率与成绩计算分别管理。
- [x] 统一停止、暂停、课程切换、设备断线与异步初始化的清理流程，为每轮练习分配唯一标识。

### 验收条件

- 找音、跟拍、分手、另一声部伴奏、循环、预备拍、试听与章节完成流程均通过回归验证。
- 同一组输入与相同设置在可控时钟下产生一致成绩，界面刷新频率变化时判定结果一致。
- 快速开始与停止、暂停后切课、断线重连等流程能正确释放声音和按键状态，过期异步结果得到丢弃。
- 每轮练习的成绩只结算一次，重试保存能够按练习标识去重。

## 统一输入与播放时间基准

### 当前实现

`src/midi.ts` 将消息字节、事件时间、时间来源和连接会话一同传给练习室。桌面保留 midir 时间戳，通过原生单调时钟与 WebView 的往返采样对齐页面时钟；浏览器使用 Web MIDI 事件时间戳，缺失或无效时回退到接收时刻。每次重连重新对时，并丢弃旧会话的事件。[midir 输入回调](https://docs.rs/midir/latest/midir/struct.MidiInput.html#method.connect) · [Web MIDI 事件](https://www.w3.org/TR/webmidi/#midimessageevent-interface)

`src/midiTiming.ts` 把事件时刻换算到 Web Audio 时间轴；按键和松键共用同一套拍点及手动补偿计算。实时发声仍在收到输入时触发。可控时钟回归覆盖不同的投递延迟以及提前、滞后和时值偏差；浏览器回归覆盖将两组按下与松开消息延迟到第三拍一起送达的情况。测试入口为 `src/midiTiming.test.ts`、`src/midi.test.ts` 和 `tests/browser/midiTiming.pw.ts`。设备端延迟和跨系统休眠行为仍待实测。

### 实施任务

- [x] 为桌面与浏览器输入定义统一事件结构，包含原始消息、事件时间、时间来源与连接会话标识。
- [x] 保留原生 MIDI 时间戳与浏览器输入时间戳，建立输入时钟到音频时钟的映射。
- [ ] 为设备重连、音频上下文恢复和系统休眠恢复重新建立时钟映射。
- [ ] 明确预备拍、暂停恢复、变速和循环的时间原点，让判定、声音、谱面光标和手势消费同一演奏位置。
- [ ] 按设备保存校准参数，分别记录输入事件传递延迟、音频输出延迟和抖动。
- [ ] 在 MIDIPLUS 实机上测量空闲、长谱滚动和 3D 动画运行时的表现，记录设备、系统、音频输出与测量方法。

### 验收条件

- 对事件施加不同的传递延迟后，带有效时间戳的相同输入能得到一致的节奏判定。
- 重连与恢复后时间位置连续且合理，旧会话事件能够被识别并丢弃。
- 谱面播放线、示范声音、节拍器与手势在预备拍、循环和恢复后能够对齐。
- 测量报告包含中位数、P95、异常峰值与样本条件。基于实际设备建立性能目标，并用同一条件复测。

## 完善乐谱模型与长谱体验

### 当前实现

`src/model.ts` 以音高、开始拍、时值、左右手和指号表示练习音符。`src/import.ts` 对反复、延音线、连音组、多声部交叠、拍号变化和乐谱长度设有限制。谱面通过 `src/scoreMusicXml.ts` 重新生成，再交给 `src/Score.tsx` 展示。

复杂曲目需要同时保存谱面语义与实际演奏顺序。OSMD 可继续承担 MusicXML 排版与交互，应用侧完善输入模型和播放映射。[OSMD 官方介绍](https://opensheetmusicdisplay.org/)

### 实施任务

- [ ] 为乐谱定义版本、稳定音符标识、小节、声部、休止、拍号、速度、调号和指法结构。
- [ ] 按实际曲目逐项增加弱起、跨小节延音、同手多声部、连音组及反复等语义，每项配备对应样例。
- [ ] 保存导入的原始谱文件与解析结果，记录暂未支持的特性和用户可采取的处理方式。
- [ ] 从乐谱生成演奏时间线，记录每次演奏事件对应的原谱音符及反复次数，支持反复段和循环段定位。
- [ ] 让声音、判定、播放线和手势共同使用演奏时间线，按需要生成分手与简化练习版本。
- [ ] 将乐谱布局计算与光标移动分开，按段或按页缓存布局，连续播放时预加载后续谱面。
- [ ] 以现有短谱、128 小节谱和 512 小节谱作为初始性能样例，记录加载耗时、内存、滚动和光标表现。这些规模用于测试，产品导入范围随验证结果调整。

### 验收条件

- 新增谱面特性在显示、声音和判定中具有一致含义，反复播放的同一音符按演奏次数分别判定。
- 选段、分手、变速、循环与暂停恢复能准确定位到原谱音符。
- 练习过程中五线谱、当前播放线、键盘和手势持续可见，跨页和跨段时保持阅读上下文。
- 长谱播放时光标更新复用已有布局，缩放、窗口变化和滚动后的音符定位准确。
- 旧课程与已导入短谱能经过版本适配正常进入学习和练习流程。

## 引入持久数据层与课程版本

### 当前实现

`src/storage.ts` 使用 localStorage 保存学习记录、练习进度和导入谱。练习历史最多保留 200 条，`src/progress.ts` 另外维护累计完成等级。随着课程内容修订、乐谱增加和历史分析需求增长，需要明确数据版本与恢复路径。

### 实施任务

- [ ] 采用 SQLite 管理课程版本、学习进度、练习记录、导入谱元数据与设备校准参数。音视频和原始谱文件存放于应用数据目录。
- [ ] 通过存储接口接入桌面数据库，浏览器预览使用对应存储适配。小型界面偏好继续使用轻量存储。
- [ ] 为课程、章节、自查项和练习记录设置稳定标识，课程更名、重排和内容修订通过版本关系处理。
- [ ] 为现有 localStorage 数据实现可重复执行的迁移，校验条数、标识和完成等级，在事务成功后记录迁移状态。
- [ ] 增加数据库版本迁移、数据导出与恢复流程，明确重复记录的合并规则。
- [ ] 将单轮成绩和对应进度更新放入同一事务，保存失败时保留可重试的数据并反馈状态。

Tauri 官方 SQL 插件支持 SQLite 和数据库版本迁移，可作为实现起点。数据库迁移在事务内执行，失败时回滚。[Tauri SQL 插件](https://v2.tauri.app/plugin/sql/)

### 验收条件

- 旧版记录、导入谱、自查结果与累计完成等级迁移后可读，迁移重试能识别已处理数据。
- 模拟写入失败、中途退出与升级失败后，原数据可恢复，成绩与课程进度保持一致。
- 课程重排、更名或新增自查项时，已有完成记录依据版本规则得到正确关联。
- 导出后在新数据目录恢复，课程进度、历史记录与谱文件引用完整。
- 练习记录增长后支持分页查询，用户能从界面明确获知数据保存失败并重试。

## 精细化手势与指法教学

### 当前实现

现有 3D 功能使用 Ultraleap 手模、Three.js 骨骼动画及 CCDIKSolver，并提供俯视与拇指特写。主要入口为 `src/HandKeyboard.tsx`、`src/fingeringPose.ts`、`src/pianoHandRig.ts` 和 `src/pianoScene.ts`。动作由课程指法与音符驱动，MIDI 提供音高和触键事件，手指选择由学习者对照示范确认。

### 实施任务

- [ ] 将指法动作表达为准备、落键、保持、释放和移动阶段，支持手位、手腕与指间协调。
- [ ] 为穿指、跨指、同音换指、保持音和双手移动建立经过教学核对的动作样例。
- [ ] 将动作绑定到谱面音符和演奏事件，支持慢放、暂停观察、循环以及不同速度下的连续过渡。
- [ ] 对穿指和跨指配置可观察接触位置的镜头，结合当前手别调整局部特写。
- [ ] 调整材质、灯光、接触阴影和关节形变，确保动作重点清晰，记录关键帧便于比较。

### 验收条件

- 左右手的代表性换指样例均可观察到动作准备、接触与释放过程。
- 慢放、暂停、循环和变速后的手势与目标音符位置一致，动作连接自然。
- 教学样例检查手指交叉、关节角度和琴键接触，发现的问题能定位到具体动作数据。
- 在练习页面同时观察完整键位和局部动作，谱面阅读与播放控件保持可用。

## 按测量结果改善音源与多平台体验

### 音源演进

当前钢琴音色使用九个采样音，通过变速覆盖其他音高，力度控制音量。后续可评估更密集的音区采样、多力度层、释放音和踏板效果，结合音色试听、内存、加载时间与并发发声表现选择成熟方案。

- [ ] 在音频接口后评估采样器与音源方案，记录许可证、离线资源、踏板和力度支持情况。
- [ ] 对复杂实时处理评估 AudioWorklet，对实际设备上仍未达到延迟目标的场景评估原生音频引擎。
- [ ] 使用同一组练习与输入记录比较音质、延迟、资源占用和停止清理行为。

AudioWorklet 支持在独立音频线程上执行自定义处理。具体收益需要根据音源负载和目标设备测量。[AudioWorklet 文档](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet)

### 平台验证

- [ ] 先建立 Windows 实机基线，覆盖 MIDIPLUS 连接、力度、踏板、断线、音频恢复、长谱和 3D 同时运行。
- [ ] 启动 Linux 或 macOS 交付时，增加对应系统的构建、安装、MIDI、音频、字体和图形验证。
- [ ] 为各平台记录系统与 WebView 版本、设备连接方式、性能结果和已知限制，按实际验证结果声明支持范围。
